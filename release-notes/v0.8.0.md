# Release Notes — GoGraph v0.8.0

**Date:** 2026-07-14
**Tag:** `v0.8.0`
**Module:** `github.com/FlavioCFOliveira/GoGraph`
**Status:** Pre-1.0 (unstable public API)

---

## Overview

GoGraph v0.8.0 is the tenth published release of GoGraph, a Go module
for graph **persistence**, **manipulation**, and — above all — **fast
search**, designed to scale from in-memory graphs to graphs that exceed
RAM.

This is a pre-1.0 **MINOR** release. Its headline is **correctness and
security hardening**, driven by three consecutive multi-specialist
audits — of the INDEX feature, the CONSTRAINT feature, and a
whole-module production-readiness review with a round-2 re-audit. The
headline additions and fixes are:

- **Modern openCypher `FOR ... REQUIRE` constraint syntax.** `CREATE
  CONSTRAINT [name] [IF NOT EXISTS] FOR (n:Label) REQUIRE n.prop IS
  UNIQUE | IS NOT NULL` — the grammar every current Neo4j driver, shell,
  and migration tool emits — is now accepted and enforced, closing the
  main production-interoperability blocker for the constraint feature.
  This is the sole net-new module capability in the release.
- **Schema-DDL durability and atomicity fixes.** A `CREATE` / `DROP`
  constraint or index whose WAL commit failed can no longer persist
  across a restart under a concurrent checkpoint (an Atomicity fix), and
  recovered `UNIQUE` / `NOT NULL` constraints are no longer silently left
  unenforced when a store is reopened with the plain constructor (a
  Consistency fix).
- **A denial-of-service and out-of-memory hardening pass** across the
  Cypher evaluator, the snapshot and WAL recovery readers, and the Bolt
  protocol: a value-nesting-depth cap closes an authenticated
  stack-overflow crash, several recovery readers are bounded against a
  crafted or corrupted file, and Bolt `COMMIT` / `ROLLBACK` now require
  authentication.
- **A `crypto/tls` CVE cleared by a toolchain bump to `go1.26.5`**
  (`GO-2026-5856` / `CVE-2026-42505`).
- **`UNIQUE` numeric identity now uses value-equivalence** (`1` and `1.0`
  are the same constrained value), aligning the constraint with
  openCypher `=`, GoGraph's own `MERGE`, and Neo4j.

## Semantic-versioning rationale

The bump is **MINOR** under [Semantic Versioning](https://semver.org/).
The `FOR ... REQUIRE` constraint grammar is net-new, additive Cypher
surface; every other change is an **internal** fix, a security or
denial-of-service hardening, a toolchain patch, or test and documentation
work that restores a previously-documented contract or closes a hardening
gap. The 86 commits landed since `v0.7.0` were surveyed
(`git log --no-merges v0.7.0..HEAD`) and **no breaking change to the
exported Go API** was found, so there is no "Breaking" note in this
release. Per the project's own rule, the examples and the
deterministic-simulation (DST) harness are **not part of the module** —
they exercise it but expand no public API, so the 20 example commits and
the DST commits appear under [Testing and tooling](#testing-and-tooling)
and never as new functionality. As a `0.y.z` release the public API
nonetheless remains unstable: it may change without a major-version bump
while the module matures toward `1.0.0`. **Pin the exact version you
depend on.**

## Compliance mandates — affirmed

Both compliance guarantees that define the project continue to hold
without regression at this version:

- **100 % openCypher TCK-compliant at the execution level** — every
  scenario in `cypher/tck/features/` passes, with no `failed`,
  `undefined`, or `pending` step. Re-verified for this release with
  `go test -run TestTCKExecution ./cypher/tck/`: the execution gate
  stands at **3 897 / 3 897 scenarios** and **16 006 / 16 006 steps**,
  0 failed, 0 undefined. The regression gate
  (`tckExecutionBaseline = 3897` in `cypher/tck/runner_test.go`) is
  unchanged. The one new module capability (`FOR ... REQUIRE`) is
  TCK-neutral, because index and constraint DDL is not TCK-covered.
- **100 % ACID-compliant** — Atomicity, Consistency, Isolation, and
  Durability hold across the in-memory engine and every persistence
  backend, verified by the deterministic crash-injection battery
  (`internal/crashinject/`), the WAL recovery tests (`store/wal/`,
  `store/recovery/`), and the expanded DST scenarios. This release
  **strengthens** the guarantee directly:
  - **Atomicity** — a schema-DDL statement whose fsync failed can no
    longer be published by a concurrent checkpoint and enforced or
    applied after a restart (#1902 / #1919).
  - **Consistency** — recovered constraints are auto-enforced instead of
    silently ignored (#1981); a nested or map property value the snapshot
    codec cannot serialise is rejected fail-stop instead of stored
    (findings F3); the constraint registry no longer aliases a dotted
    label and property (#1916); and `UNIQUE` numeric identity matches
    openCypher value equality (#1910).
  - **Durability** — index-def registry updates occur inside the DDL
    single-writer window, so a WAL-truncating checkpoint never persists a
    `(watermark, defs)` pair inconsistent with the WAL (#1894); several
    recovery readers are bounded so a corrupt file degrades to the safe
    rebuild path rather than crashing (findings F2, R1; #1901, #1915).

The Go toolchain is now **go1.26.5** (bumped from `go1.26.4` to clear the
`crypto/tls` advisory below), and `govulncheck ./...` reports no
vulnerabilities.

Install with:

```bash
go get github.com/FlavioCFOliveira/GoGraph@v0.8.0
```

The Go module path is `github.com/FlavioCFOliveira/GoGraph` with **no**
`/vN` suffix, which is Semantic-Import-Versioning-correct for a `0.x`
line.

## Highlights

- **Modern openCypher `FOR ... REQUIRE` constraint grammar.** The DDL
  parser previously accepted only the legacy `ON (n:Label) ASSERT ...`
  form Neo4j removed in 5, rejecting the current `CREATE CONSTRAINT
  [name] [IF NOT EXISTS] FOR (n:Label) REQUIRE n.prop IS UNIQUE |
  IS NOT NULL` with a misleading "expected ON" error and mis-parsing the
  `FOR` keyword as the constraint name. Both grammars now map to the same
  IR and are actually enforced; unsupported forms (relationship,
  composite, `NODE KEY`, and `IS :: <TYPE>` property-type constraints)
  are rejected with a specific, actionable error. (#1906)
- **Failed schema-DDL is no longer durable.** A `CREATE` / `DROP`
  constraint or index whose WAL commit failed at fsync could, under a
  concurrent non-blocking checkpoint, be captured from the transient
  in-memory registry and published into `constraints.bin` /
  `indexdefs.bin`, then enforced or applied after a restart — a change
  the client saw fail. The checkpoint's phase-1 capture now consults a
  new `wal.Writer.Poisoned()` probe and aborts before publishing when the
  writer is poisoned. (#1902, #1919)
- **Recovered constraints are auto-enforced.** Opening a persisted
  database with the plain `NewEngineWithStore` left durable
  `UNIQUE` / `NOT NULL` constraints unregistered and silently unenforced;
  the constructor now auto-registers them from the graph's durable
  store-direct set and warns when durable constraints are present but
  unregistered. A new `lpg.Graph.StoreConstraints` getter exposes the
  set. (#1981)
- **Authenticated stack-overflow DoS closed.** A short query building a
  multi-million-deep nested value could overflow the goroutine stack in a
  recursive walker — a fatal crash `recover()` cannot catch. `reduce()`
  now rejects an over-deep or over-large accumulator with a typed
  `EvalError`, and PackStream `WriteValue` enforces the symmetric depth
  bound. (finding F1)
- **`crypto/tls` CVE cleared.** The toolchain is bumped to `go1.26.5` to
  clear `GO-2026-5856` / `CVE-2026-42505` (Encrypted Client Hello
  de-anonymization), reachable by symbol through the Bolt TLS path though
  unreachable in practice because GoGraph never configures ECH. (#2003)
- **`UNIQUE` numeric value-equivalence.** The integer `1` and the float
  `1.0` are now the same constrained value (and `+0.0 == -0.0 == 0`, and
  every `NaN` collapses to one key), matching openCypher `=`, `MERGE`
  (aligned in #1240), and Neo4j — while values beyond `2^53` that round
  to the same `float64` stay distinct to preserve transitivity. (#1910)
- **Bolt `COMMIT` / `ROLLBACK` require authentication.** A session left
  in `TX_READY` but unauthenticated after `LOGOFF` could still finalise
  its transaction; both handlers now also require `s.authenticated`,
  mirroring `RUN` / `BEGIN` / `ROUTE`. (finding F5, CWE-306)

## What changed

### Modern `FOR ... REQUIRE` constraint syntax

```cypher
CREATE CONSTRAINT unique_email IF NOT EXISTS
  FOR (u:User) REQUIRE u.email IS UNIQUE;

CREATE CONSTRAINT name_present
  FOR (u:User) REQUIRE u.name IS NOT NULL;
```

`parseCreateConstraint` now accepts `FOR ... REQUIRE` as the primary
grammar and keeps `ON ... ASSERT` as a legacy alias; the optional-name
detection excludes `FOR`, so the keyword is no longer swallowed as a
name. Both grammars produce the same IR and are validated and enforced —
including retroactive rejection of pre-existing `UNIQUE` duplicates and
`NOT NULL` nulls at `CREATE CONSTRAINT` time. Out-of-scope forms
(relationship constraints, composite/multi-property constraints,
`NODE KEY` / relationship key, and property-type `IS :: <TYPE>`
constraints) are recognised and rejected with a specific error rather
than a confusing parse failure. Index and constraint DDL is not
TCK-covered, so this is additive with no conformance impact. (#1906)

### Constraint and index durability and atomicity

The CONSTRAINT and INDEX audits (rmp sprints 265–266) closed a cluster of
schema-DDL persistence gaps:

- **Failed DDL is not durable.** The checkpoint now aborts its phase-1
  capture when `wal.Writer.Poisoned()` reports the writer poisoned by a
  failed commit, so a constraint or index change the client saw fail
  never reaches `constraints.bin` / `indexdefs.bin`. (#1902, #1919)
- **Registry updates are serialised with the DDL.** `recordIndexDef` /
  `forgetIndexDef` run before `commitIndexTx` in all three WAL-backed
  paths, and `Graph.HasConstraints` flips inside the `CREATE CONSTRAINT`
  barrier, so a WAL-truncating checkpoint can never capture a
  half-transitioned registry and resurrect a dropped object or lose a
  created one across a crash. (#1894, #1917)
- **Recovery enforces what was declared.** `NewEngineWithStore`
  auto-registers durable constraints, and a regression gate pins that a
  dropped constraint is not resurrected across a checkpoint. (#1981,
  #1920)
- **The durable boundary is width-safe.** A DDL identifier over the
  parser cap (`maxSchemaIdentifierLen = 4096`) is rejected fail-stop, and
  the WAL and snapshot encoders are reconciled so an oversized name,
  label, or property can never be silently truncated on one path and
  rejected on another. (#1903)

### Cypher correctness

- **`MERGE ... ON CREATE / ON MATCH SET` evaluates an expression RHS.** A
  self-referential `MERGE (n) ON MATCH SET n.num = n.num + 1` used to
  commit but never increment — a fail-silent Consistency defect the TCK
  does not cover. The IR now carries the non-literal set-item value ASTs
  to the physical builder, which evaluates each against a
  schema-consistent row with the matched entity and its current
  properties bound. (#1965)
- **`SET` / `MERGE`-`SET` RHS evaluation errors are surfaced.** The write
  path used to discard an evaluation error and return a silent no-op; it
  now propagates the error so the statement aborts and rolls back
  atomically. (sprint 277, Cypher F1)
- **Nested-collection and map property values are rejected fail-stop**
  with `InvalidPropertyType` on every write path (`CREATE` inline node
  and relationship, `MERGE ON CREATE` / `ON MATCH SET`, `MERGE`-pattern
  search props, and whole-entity `SET n =` / `SET n +=`), closing a
  store inconsistency the snapshot codec cannot serialise. Flat lists of
  primitives remain valid. (findings F3)
- **`UNIQUE` idempotent self-set succeeds.** Setting a `UNIQUE` property
  to the value the node already holds no longer trips its own
  reservation, and the previously-leaked phantom reservation on a
  replaced value is released across `SET` and both `MERGE` set executors.
  (#1905, #1904)
- **Range-seek correctness.** The unbounded-above string range seek is
  open-ended (`btree.RangeFrom` / `RangeCountFrom`) instead of a fixed
  32-byte sentinel that silently dropped a key sorting above it, and
  `NodeByIndexRangeScan` drops a meaningless exclusive-bound `NodeID`
  comparison, emitting an honest inclusive superset the residual `Filter`
  refines. Neither is reachable with valid input from the Cypher engine,
  so the TCK baseline is unaffected. (#1895, #1897)

### Security and denial-of-service hardening

The 2026-07-13 production-readiness audit and its round-2 re-audit (rmp
sprints 277–278) closed a set of DoS, OOM, and defence-in-depth gaps.
None affect a well-formed store written by GoGraph itself or a trusted
caller; they are reachable only from a hostile query, a crafted or
corrupted file, or a state-transition edge case:

- **CVE / toolchain.** The Go toolchain is bumped to `go1.26.5` to clear
  `GO-2026-5856` / `CVE-2026-42505`, a `crypto/tls` Encrypted Client
  Hello de-anonymization advisory reachable by symbol through the Bolt
  TLS path. GoGraph never configures ECH, so the behaviour is unreachable
  in practice, but a release must not pin a toolchain with an open
  `crypto/tls` advisory. `govulncheck ./...` reports no vulnerabilities
  on `go1.26.5`. (#2003)
- **Stack-overflow DoS.** `reduce()` rejects an over-deep or over-large
  accumulator with a typed `EvalError` (via the iterative, alias-robust
  `expr.ExceedsValueDepth` against `expr.MaxValueDepth`), and PackStream
  `WriteValue` enforces the symmetric `maxValueDepth` bound
  (`ErrNestingTooDeep`), closing an authenticated whole-process crash.
  (finding F1)
- **Bounded recovery readers.** `store/snapshot`'s `readIndexFile` is
  bounded by the manifest-declared size (finding F2, CWE-770 / CWE-789);
  `constraints.bin` and `indexdefs.bin` reads are bounded before the CRC
  is verified, with eager pre-allocation dropped (#1915, #1901); and the
  `PropList` recovery decode caps its eager reservation, which was
  roughly `4.8×` the remaining wire bytes and could reach several GiB for
  a hostile count (round-2 finding R1, CWE-770 / CWE-789).
- **Bolt authentication.** `COMMIT` and `ROLLBACK` now require
  `s.authenticated`, closing a missing-auth-on-state-transition gap for a
  session left in `TX_READY` but unauthenticated after `LOGOFF`. Defence
  in depth — only already-authorised writes were ever reachable. (finding
  F5, CWE-306)

### Performance

- **`NOT NULL` existence check.** A copy-on-write `label → NOT-NULL-
  properties` index replaces a per-node locked full-map scan plus a fresh
  slice allocation at commit time. The targeted `BenchmarkNotNullProperties`
  over 257 constraints reports 6.3 ns/op, 0 B/op, 0 allocs/op. (#1911)
- This release contains **no performance-focused work** beyond that
  targeted micro-optimisation; see
  [Benchmark evidence summary](#benchmark-evidence-summary).

### Documentation

The audits also corrected documentation that had drifted from the code:
`docs/cypher.md` now shows `FOR ... REQUIRE` as the primary constraint
grammar, documents retroactive data validation and constraint-name
uniqueness, and corrects a false "btree index supports `ORDER BY`" claim
to the real range-predicate-only capability (#1913). The secondary-index
write-path contract is documented (pick one write path per graph, because
raw `txn.Store` writes bypass Engine-managed index updates) (#1980), a
stale godoc claiming `elementId()` is unimplemented is fixed (#1978), and
the `int64` hash-index and `Index.Apply` subscriber-ordering contracts
are stated, with `KShortestPathsLoopless` callers steered toward the
bounded or polynomial variants for untrusted input (#1900, #1898, #2006).

- **DST coverage expanded** across sprints 267–270: schema-mutation and

## Upgrade notes

- **No migration required.** Stores written by earlier releases open
  without conversion. The `FOR ... REQUIRE` grammar is additive; existing
  code and queries compile and behave unchanged.
- **Enforce recovered constraints with a schema-aware constructor.** If
  you reopen a persisted database that declared `UNIQUE` / `NOT NULL`
  constraints, prefer `NewEngineWithStoreAndConstraints` or
  `NewEngineWithStoreAndSchema` to carry the original constraint names
  and re-register secondary indexes. The plain `NewEngineWithStore` now
  auto-enforces recovered constraints (using synthesised deterministic
  names) and warns when durable constraints are present but unregistered,
  so enforcement is never silently disabled — but the schema-aware
  constructors remain the recommended path.
- **`UNIQUE` now treats `1` and `1.0` as the same value (bug fix).** If
  your application relied on the previous behaviour that admitted both an
  integer and its equal float under one `UNIQUE` constraint, the second
  insert is now rejected as a duplicate, matching openCypher and Neo4j.
- **A nested or map property value is now rejected (bug fix).** A write
  that previously stored or silently dropped a nested list or a map as a
  single property value now fails fast with `InvalidPropertyType`. Use a
  flat list of primitives, or a whole-map form (`SET n = {scalar map}`)
  that assigns a group of scalar properties.
- **Bolt clients must be authenticated to `COMMIT` / `ROLLBACK`.** A
  session that sent `LOGOFF` mid-transaction must re-authenticate
  (`LOGON`) before finalising; this only affects a previously
  unauthenticated state transition.
- **Pin the exact version.** As a `0.y.z` release the public API may
  still change without a major bump.

## Benchmark evidence summary

This release contains **no performance-focused work**. The one
performance change is a targeted micro-optimisation of the commit-time
`NOT NULL` existence check to an O(1), allocation-free lookup
(`BenchmarkNotNullProperties`: 6.3 ns/op, 0 B/op, 0 allocs/op; #1911);
every other change is a correctness, security, documentation, or testing
change with no intended effect on the hot paths.

The headline guard-band benchmarks are therefore expected to be
**unchanged versus `v0.7.0`, with no measured regressions**. The
authoritative measured figures for this release — the guard-band set and
the `v0.7.0 → v0.8.0` comparison — are recorded in
[docs/benchmarks/v0.8.0.md](../docs/benchmarks/v0.8.0.md), measured on
the run environment documented there. The two post-warmup traversal paths
continue to allocate **zero** bytes per call, confirming the
zero-allocation hot-path mandate still holds for the reusable-state query
forms. Consult that document for the per-benchmark numbers; no benchmark
figure in these notes should be read as a substitute for it.
