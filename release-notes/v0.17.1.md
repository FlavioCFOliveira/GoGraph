# Release Notes — GoGraph v0.17.1

**Release date:** 2026-10-13 (pending the tag)
**Tag:** `v0.17.1`
**Previous release:** [`v0.17.0`](v0.17.0.md) (2026-10-13)
**Module path:** `github.com/FlavioCFOliveira/GoGraph`
**Go toolchain:** `go.mod` pins `go 1.26` and `toolchain go1.27.2`.
`go.mod` and `go.sum` are byte-identical at `v0.17.0` and `4743de3d`: no dependency moved in
this window.

## Read this first

**`v0.17.1` is a drop-in PATCH release. Embedders pinned to `v0.15.0`, `v0.16.0` or `v0.17.0`
should move their pin to `v0.17.1`.**

1. **A rolled-back write transaction no longer leaks memory.** Since `v0.15.0`, a transaction
   that created nodes and then aborted as a whole kept the keys it had minted for `CREATE ()`
   interned in `graph.Mapper`, with its write set. A long statement cut by its deadline could
   leave gigabytes live. See [Fixes](#fixes).
2. **No exported API change and no format change.** No exported identifier was added, removed
   or re-signed; no WAL, snapshot or other on-disk format changed. A store written by `v0.17.0`
   opens unchanged, and `v0.17.0` can still open a store written by `v0.17.1`.
3. **One observable behaviour change:** `(*graph.Mapper).MaxNodeID` no longer counts holes
   trimmed from the end of a shard. See [Behaviour changes you can observe](#behaviour-changes-you-can-observe).

## Fixes

### A rolled-back write statement no longer leaves its node keys interned (rmp #3119, #3120)

Present in `v0.15.0`, `v0.16.0` and `v0.17.0`. When a transaction that created nodes aborted as
a whole — an autocommit statement cut by its context deadline, a failed or refused statement, or
an explicit transaction rolled back — the anonymous keys it minted for `CREATE ()` stayed in
`graph.Mapper`, together with the transaction's write set, adjacency-version entries and unborn
marks.

The abort now releases every never-born node created under a minted key: the key no longer
resolves, its id becomes a hole, the tombstone and unborn marks are cleared together, and the
Mapper gives the memory back. Oversized transaction states are not recycled, and empty
adjacency stamps are dropped at abort (`78039599`).

What does not change:

- Committed ids and `elementId()` values are unchanged.
- Ids are never issued twice: the shard's high-water mark is not lowered, so a later intern of
  the same key receives a new id.
- A statement that fails inside a transaction that later commits keeps its bindings, as before.

### New keys after a large rollback no longer re-create the released range (rmp #3121)

Ids are never reissued, so the first keys interned after a large rollback land past the released
range, and the dense reverse table re-created that range as holes, about 16 B per released id. A
shard now keeps such a run of holes at its end unallocated and holds later keys in 64-slot pages
allocated on demand and freed when emptied. The dense table and its hot paths are unchanged
(`54a2e218`).

**Residual cost:** holes in the middle of a shard — nodes committed in the same shard while a
large statement was rolled back — still cost about 16 B per id.

## Changes by area

The complete list is the `## [0.17.1]` entry of [CHANGELOG.md](../CHANGELOG.md).

- **Graph core:** `graph.Mapper` trims trailing holes, frees emptied tail pages and rebuilds its
  forward map once deletions outnumber live keys; `Unplace` now also serves transaction abort.
- **LPG engine:** transaction abort releases the minted keys of never-born nodes and the
  associated write-set, adjacency-version and unborn state.
- **Cypher:** the synthetic-key prefix `__cx_` moved to `internal/synthkey` so that `graph/lpg`
  and `cypher/exec` share one definition; the value is unchanged.
- **Internal:** new package `internal/synthkey` (not part of the exported API).

## Behaviour changes you can observe

- `(*graph.Mapper).MaxNodeID` no longer counts holes trimmed from the end of a shard. After a
  rollback that released the last ids of a shard, it can return a smaller value than `v0.17.0`
  returned for the same history. It still covers every bound id, including those held in a
  shard's tail pages (`graph/mapper.go`, `endLocked`).
- After an aborted transaction, a key it minted no longer resolves through the Mapper.
- Rolling back a transaction that created many nodes takes longer: about 1.5 s per about 1.6 M
  released ids (see [Performance](#performance)).

(#3119 to #3121) on the code this release ships. The rows measure different workloads and are

## Upgrade

**Upgrade is drop-in.** Change the version in `go.mod`:

```bash
go get github.com/FlavioCFOliveira/GoGraph@v0.17.1
```

No code change, no migration and no store rewrite is needed. A store written by `v0.17.0` opens
as is; the WAL and snapshot formats are those of `v0.17.0`, so a downgrade to `v0.17.0` remains
possible. Embedders still on `v0.15.0` or `v0.16.0` must also apply the migration notes of
[`v0.16.0`](v0.16.0.md) and [`v0.17.0`](v0.17.0.md).

## Compliance mandates

- **openCypher TCK:** `tckExecutionBaseline` is 3 897 and no feature file changed.
- **ACID:** abort now releases the state of never-born nodes only; committed bindings and ids are
  untouched, and ids are never reissued, so Atomicity and Durability of committed work are
  unaffected.
- **Efficiency:** the release removes a memory leak on rollback; see [Performance](#performance).
- **Security:** no toolchain or dependency change.
