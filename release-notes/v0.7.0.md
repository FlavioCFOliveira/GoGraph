# Release Notes — GoGraph v0.7.0

**Date:** 2026-07-03
**Tag:** `v0.7.0`
**Module:** `github.com/FlavioCFOliveira/GoGraph`
**Status:** Pre-1.0 (unstable public API)

---

## Overview

GoGraph v0.7.0 is the ninth published release of GoGraph, a Go module
for graph **persistence**, **manipulation**, and — above all — **fast
search**, designed to scale from in-memory graphs to graphs that exceed
RAM.

This is a pre-1.0 **MINOR** release. Its headline is **openCypher
completeness and correctness**, backed by four consecutive
multi-specialist production-readiness and security audit rounds. The
headline additions and fixes are:

- **Eight new openCypher builtin functions** — `elementId`, `timestamp`,
  `randomUUID`, `isNaN`, and the `toStringList`/`toIntegerList`/
  `toFloatList`/`toBooleanList` family — closing a functional-
  completeness gap that previously blocked real-world Cypher workload
  migration.
- **`MERGE` whole-pattern match-or-create semantics.** The single most
  common Cypher graph-building idiom — `MERGE
  (a)-[:R]->(b)` with a fresh endpoint — now creates the whole pattern
  correctly instead of silently creating only the first node.
- **A parallel edge on a non-multigraph engine is rejected, not silently
  dropped**, closing a genuine write-loss gap on the documented default
  engine configuration.
- **A broad security and denial-of-service hardening pass** across the
  WAL, snapshot, index, Bolt protocol, and CSV/GraphML/JSONL interchange
  formats: bounded allocations, `O(n²)` DoS guards, and symlink-attack
  rejection (`O_NOFOLLOW`) on every file the engine opens by name.
- **The `O(V+E)` edge-type filter is cached across queries**, cutting a
  repeated selective relationship-type query from ≈190 ms/2.16 M
  allocs to ≈30 ms/336 K allocs on a 120k-node graph.

## Semantic-versioning rationale

The bump is **MINOR** under [Semantic Versioning](https://semver.org/).
The eight new builtin functions are net-new, additive Cypher surface;
every other change is an **internal** fix that restores a
previously-documented contract or closes a hardening gap. The 94 commits
landed since `v0.6.0` were surveyed (`git log v0.6.0..HEAD`) and **no
breaking change to the exported Go API** was found, so there is no
"Breaking" note in this release. As a `0.y.z` release the public API
nonetheless remains unstable: it may change without a major-version bump
while the module matures toward `1.0.0`. **Pin the exact version you
depend on.**

## Compliance mandates — affirmed

Both compliance guarantees that define the project continue to hold
without regression at this version:

- **100 % openCypher TCK-compliant at the execution level** — every
  scenario in `cypher/tck/features/` passes, with no `failed`,
  `undefined`, or `pending` step. The execution gate stands at
  **3 897 / 3 897 scenarios** and **16 006 / 16 006 steps**. The
  regression gate (`tckExecutionBaseline = 3897` in
  `cypher/tck/runner_test.go`) is unchanged.
- **100 % ACID-compliant** — Atomicity, Consistency, Isolation, and
  Durability hold across the in-memory engine and every persistence
  backend, verified by the deterministic crash-injection battery
  (`internal/crashinject/`) and the WAL recovery tests
  (`store/wal/`, `store/recovery/`). This release **strengthens** that
  guarantee directly: the `MERGE` whole-pattern fix and the
  reject-instead-of-drop parallel-edge fix are both Consistency fixes in
  the ACID sense — a write that used to silently vanish or apply only
  partially now either fully applies or is rejected with a typed error,
  never a partial, silent result. The WAL `O(n²)` torn-tail DoS guard and
  the CSR weight-width recovery check are Durability and Consistency
  hardening on the recovery path specifically.

The Go toolchain remains **go1.26.4** (unchanged from `v0.6.0`), and
`govulncheck ./...` stays clean.

Install with:

```bash
go get github.com/FlavioCFOliveira/GoGraph@v0.7.0
```

The Go module path is `github.com/FlavioCFOliveira/GoGraph` with **no**
`/vN` suffix, which is Semantic-Import-Versioning-correct for a `0.x`
line.

## Highlights

- **Eight new openCypher builtin functions.** `elementId(node|rel)`, the
  recommended replacement for the deprecated `id()`; `timestamp()`,
  statement-frozen milliseconds since the Unix epoch; `randomUUID()`, an
  RFC 4122 v4 UUID; `isNaN(number)`; and the element-wise
  `toStringList`/`toIntegerList`/`toFloatList`/`toBooleanList` scalar
  conversion family. All eight are TCK-neutral, so the 3 897-scenario
  baseline is unchanged. (#1832)
- **`MERGE` whole-pattern match-or-create.** A new left-deep join search
  (`ir.MergePattern`/`exec.MergePattern`) handles any relationship chain
  with a fresh endpoint — the pattern the narrow single-relationship
  fast path did not cover — with an atomic create-everything-missing
  fallback. `Engine.Run` now rejects a write-clause query with a clear
  pointer at `RunInTx`/`RunAny` instead of an opaque error. (#1866)
- **Parallel edges rejected on a non-multigraph engine.** `CREATE`ing a
  second relationship between two already-connected nodes on the
  documented default configuration used to report success while storing
  nothing; it now fails the statement up front with
  `ErrParallelEdgeInSimpleGraph`. (#1856)
- **Cross-type numeric hashing consistency.** `EquivalentHash` now hashes
  an `Integer` through the same float64 domain as an equal `Float` (and
  extends the same fix to `NodeValue`/`RelationshipValue`), so
  `DISTINCT`, `GROUP BY`, `collect(DISTINCT ...)`, and `UNION` no longer
  over-count a value that appears as both types; a sibling bug in the
  hash-join operator's own key hashing is fixed the same way. (#1857,
  #1868)
- **`MapValue.Equal` is now deterministic**, no longer dependent on Go's
  randomized map iteration order for a map pair mixing a `NULL`-yielding
  and a `FALSE`-yielding entry comparison — a definitive `FALSE` always
  wins, per openCypher's three-valued-logic conjunction (CIP2016-06-14).
- **Security and DoS hardening across four audit rounds.** WAL/CSR files
  now reject a symlinked path component (`O_NOFOLLOW`, the release's one
  HIGH-severity finding); the CSR reader is bounded by the real
  `fstat`-measured file size instead of an untrusted manifest field,
  closing a TOCTOU window; GraphML import is streamed instead of parsed
  as a full DOM; CSV/JSONL parsing, Bolt inbound-decode accounting, and
  the WAL torn-tail scan are all bounded against adversarial input. See
  [What changed](#security-and-denial-of-service-hardening) below.
- **The `O(V+E)` edge-type filter is cached across queries.** A bounded
  LRU keyed on the relationship-type set and a monotonic
  topology-generation counter turns a repeated selective query from a
  full graph rescan into a cache hit — measured ≈190 ms/2.16 M allocs →
  ≈30 ms/336 K allocs on a 120k-node/~960k-edge graph. (#1871)

## What changed

### New openCypher builtin functions

```cypher
RETURN elementId(n), timestamp(), randomUUID(), isNaN(0.0/0.0)
RETURN toStringList([1, 2.5, true]), toIntegerList(['1', 2.9, 'x'])
```

`elementId` returns the durable identifier as a decimal string — the
recommended replacement for the deprecated `id()`, with the same
node-durable / relationship-snapshot stability asymmetry. `timestamp()`
reads a statement-frozen instant, so every row of one statement observes
the same value while concurrent statements stay independent.
`randomUUID()` is `crypto/rand`-backed. `isNaN` is boolean-valued and an
integer is never NaN. Each `toXList` function converts a list
element-wise, producing `null` for a non-convertible element rather than
failing the whole call. All eight are `null` in → `null` out on a `null`
argument. (#1832)

### `MERGE` whole-pattern match-or-create semantics

`MERGE (a:L1{...})-[:R]->(b:L2{...})` with at least one fresh endpoint
previously created only the first node, silently dropping the
relationship and the second node — a genuine openCypher TCK coverage gap
(every `Merge*.feature` scenario pre-binds both endpoints, so the TCK
never exercised this shape). The fix adds a left-deep join search that
handles fresh endpoints, multi-hop chains, and node-targeted `ON
CREATE`/`ON MATCH` actions, never decomposing a partial match into
independent node reuse. Node properties get full literal/parameter/
computed-expression support; relationship properties get literal and
parameter support. A cyclic same-pattern variable reuse now rejects at
plan-build time with a clear error instead of a confusing runtime
failure. (#1866)

### Parallel-edge and cross-type hashing correctness

openCypher's data model is a multigraph: `CREATE` never deduplicates,
not even a byte-identical repeat. On the documented default engine
configuration (`Directed: true`, no `Multigraph`), creating a second
relationship between two already-connected nodes used to report success
while storing nothing. It is now rejected up front with a typed
`ErrParallelEdgeInSimpleGraph`, before any mutation or WAL frame.
(#1856)

Three related hashing gaps are closed so that `DISTINCT`, `GROUP BY`,
`collect(DISTINCT ...)`, and `UNION` treat a numerically-equal
`Integer`/`Float` pair — and a node/relationship value alongside its
raw `id()` — exactly as consistently as `Equal` already does, and so
that a hash join can no longer silently drop a matching row across the
same boundary. `distinctAggregator`'s seen-values set is capped,
bounding memory under an adversarial high-cardinality input. (#1857,
#1867, #1868)

### Security and denial-of-service hardening

Four consecutive multi-specialist audit rounds (rmp sprints 257–264)
closed every finding they raised. None of these gaps affect a
well-formed store written by GoGraph itself — they close DoS and
integrity gaps reachable only from a hostile, crafted, or corrupted
file:

- **1 HIGH** — WAL and CSR files are now opened with `O_NOFOLLOW`,
  rejecting a symlinked path component instead of following it.
  (#1843, #1847)
- **7 MEDIUM** — a mismatched CSR weight-width is rejected instead of
  panicking; the CSR reader is bounded by the real file size, not an
  untrusted manifest field (closing a TOCTOU window); an `O(n²)`
  crafted-torn-tail WAL scan is bounded; GraphML import is streamed
  instead of DOM-parsed and its `<key>`/`<data>` counts are capped; CSV
  per-record field counts and JSONL nested-list depth are bounded;
  Bolt's inbound-decode memory accounting is corrected and applies an
  engine-wide ceiling.
- **Several LOW / informational** items with documented, non-exploitable
  rationale (JSONL default cap sizing, FNV shard-hash choice).

Cypher's own resource guards were widened in the same cycle: a mandatory
statement-timeout floor now stays armed across the Bolt `RUN`/`PULL`
boundary, `shortestPath`/`allShortestPaths`' exhaustive modes and
`range()`/list-producing functions are bounded by explicit work and
evaluation budgets, and an engine-wide result-memory ceiling applies
across every connection.

`govulncheck ./...` remains clean; no Go standard-library or dependency
CVE affects this release.

### More fixes

- **DDL cancellation gaps closed.** `CREATE INDEX`/`CREATE CONSTRAINT`
  now respond promptly to context cancellation on a large graph across
  the parallel hash-index backfill, the B-tree backfill, and the `NOT
  NULL` pre-existing-data validation scan — every statement already
  completed correctly and atomically before these fixes; only
  cancellation promptness was affected. (#1869, #1872)
- **Checkpoint self-healing and documentation.** `WriteLabels`/
  `WriteProperties` self-heal a registry-capture race against a
  concurrent commit interning a new label or property key, instead of
  aborting the checkpoint attempt; `RunCheckpoint`'s godoc no longer
  falsely claims interleaved calls are safe, and `LastError` now
  reflects the most recently *started* attempt. (#1880, #1873)
- **`Yen`'s k-shortest-paths algorithm picks the min-weight parallel
  edge** in a multigraph. (#1884)
- **Empty relationship type and node label are rejected everywhere**,
  including the previously-inconsistent label-predicate expression
  form. (#1878)

### Performance

- **Edge-type filter caching.** See [Highlights](#highlights) above;
  full detail in [docs/benchmarks/v0.7.0.md](../docs/benchmarks/v0.7.0.md).
  (#1871)
- **`Dijkstra_Large`'s stray heap escape reclaimed** (5 → 4 allocs/op),
  restoring the guard-band regressed since `v0.6.0`. (#1820)

### Testing and reliability

- **A pre-existing flaky test fixed.**
  `TestJohnsonAPSPParallel_CancellationCascades` raced two unsynchronized
  timing paths on a graph too small to reliably outlast a 1 ms
  cancellation signal under heavy machine-wide CPU contention (the
  pattern `scripts/cover_gate.sh` and CI both produce by running the
  entire `./...` suite concurrently). The production cancellation-cascade
  logic under test was already correct; the test-only fix widens the
  algorithm's own uncancelled runtime by roughly three orders of
  magnitude, verified stable over 50 consecutive runs.
- Regression gates now use real `NodeID`s instead of placeholder values
  (#1863), and a deep-root-hop gate pins the Yen multigraph fix (#1884).

## Upgrade notes

- **No migration required.** Stores written by earlier releases open
  without conversion. The new builtin functions are additive: existing
  code and queries compile and behave unchanged.
- **`MERGE` behaviour change (bug fix, not a breaking change).** A
  `MERGE` pattern with a fresh endpoint that previously silently created
  only part of the pattern now creates the whole pattern correctly. If
  your application relied on the old, incomplete behaviour, review any
  `MERGE` statement with more than one entity.
- **A non-multigraph engine now rejects a parallel-edge `CREATE`** with
  `ErrParallelEdgeInSimpleGraph` instead of silently discarding it. If
  your application creates repeated relationships between the same node
  pair on a `Multigraph: false` engine, either enable `Multigraph: true`
  (if repeated relationships are intentional) or handle the new error
  (if they indicate an application bug the old behaviour was masking).
- **Pin the exact version.** As a `0.y.z` release the public API may
  still change without a major bump.
