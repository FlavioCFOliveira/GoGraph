# Release Notes — GoGraph v0.17.0

**Release date:** 2026-10-13 (pending the tag)
**Tag:** `v0.17.0`
**Previous release:** [`v0.16.0`](v0.16.0.md) (2026-10-09)
**Module path:** `github.com/FlavioCFOliveira/GoGraph`
**Go toolchain:** `go.mod` pins `go 1.26` and `toolchain go1.27.2`.
`git diff v0.16.0..e91d42b2 -- go.mod go.sum` is empty: no dependency moved in this window.

## Read this first

**`v0.17.0` breaks the exported API and changes the on-disk format.**

1. **Every graph is a directed multigraph.** Undirected graphs and simple (non-multigraph) graphs
   are no longer supported, as in Neo4j and Memgraph. `adjlist.Config.Directed`,
   `adjlist.Config.Multigraph`, `(*AdjList).Directed`, `(*AdjList).Multigraph`, the matching
   options of `graph/io/csv`, `store/bulk`, `store/bulkimport`, `store/csrfile` and
   `store/snapshot`, `cypher.ErrParallelEdgeInSimpleGraph` and the `gograph-import` flags
   `-undirected` and `-simple` are removed. See [Migration](#migration).
2. **The snapshot manifest is version 5, and older builds refuse it.** Every manifest this build
   writes is stamped 5. `v0.16.0` and every earlier build refuse a version-5 manifest with
   `snapshot.ErrManifestUnsupported`.
3. **A store written by an undirected or simple graph is migrated on its first clean open.** The
   migration rewrites the store before `Open` returns; afterwards `v0.16.0` cannot open it. Copy
   the store directory first if you need a downgrade path. See
   [On-disk format and upgrade](#on-disk-format-and-upgrade).

## Semantic-versioning classification

The version `v0.17.0` was set by the user. Under [docs/semver.md](../docs/semver.md), a `0.y.z`
release absorbs breaking changes in the MINOR digit, so a MINOR bump is the conventional class for
this content. The classification evidence: the exported surface was diffed by parsing every
non-test Go file outside `internal/`, `examples/`, `cmd/` and any `gen/`, `tck/` or `testdata/`
directory at `v0.16.0` and at `e91d42b2` — a superset of the policy's API surface. The result is
14 removals, 1 incompatible re-signing (`adjlist.Writer.AppendEdge` returns `error` instead of
`(bool, error)`) and 24 additions, one of which (`cypher/exec.(*ColumnarFilter).Close`)
redeclares a method the type already had through embedding. The snapshot manifest version also
moves from 4 to 5. After `1.0.0` the same content would require a MAJOR release.

## Highlights

### Directed multigraph only

- `graph/adjlist.AdjList` stores each edge as one directed relationship. Every `AddEdge` appends
  a new edge with its own handle, so parallel edges and self-loops are always kept. The zero value
  `adjlist.Config{}` now builds a directed multigraph.
- Every Cypher `CREATE` adds a relationship. For undirected semantics, write undirected patterns:
  `MATCH (a)-[r]-(b)` matches a relationship in either direction, and `MERGE (a)-[r:T]-(b)`
  matches either direction and, when none exists, creates one from `a` to `b`.
- The GraphML readers read each `<edge>` as one relationship from `source` to `target`, whatever
  the `edgedefault` attribute declares. The GraphML writers always emit
  `edgedefault="directed"`, and the DOT writer always emits a `digraph`.

### Undirected analytics through a symmetric projection

`graph/csr.(*CSR).BuildSymmetric` returns the undirected projection of a CSR: each non-loop arc
yields itself and its mirror with the same weight and handle, a self-loop is kept once, and
parallel arcs and reciprocal pairs are never merged. `graph/csr.BuildSymmetricFromAdjList` builds
the same projection directly from an adjacency list, and `(*CSR).KnownSymmetric` reports in O(1)
that a CSR came from either. `BuildReverse` returns such a CSR itself, so PageRank and BiBFS read
it as its own transpose.

### A shared PageRank worker budget

`search/centrality.PageRankBudget` is a caller-owned, lock-free pool of worker slots. Pass one
budget in `PageRankOptions.Budget` to every concurrent PageRank call so that together they never
start more workers than its capacity. A nil budget keeps the previous behaviour, and ranks are
bit-identical across budgets.

### Sprint 367 performance and efficiency laboratory

Every example was profiled six times across the sprint. From the first sweep (`c794a1ed`) to the
last (`8b089715`), module-attributed CPU fell 39.3 %, module-attributed allocation 29.2 % and
module contention delay 50.9 %. See [Performance](#performance).

## Changes by area

The complete, per-commit list is the `## [0.17.0]` entry of [CHANGELOG.md](../CHANGELOG.md). This
section groups it.

- **Storage and recovery:** manifest version 5 without `directed` or `multigraph` keys; legacy
  undirected and simple stores folded and checkpointed by the first clean recovery
  (`recovery.ErrLegacyMirrorConflict`, `ErrLegacyMigrationUnsupportedFS`,
  `ErrLegacyMigrationNeedsCodec`); `snapshot.LegacyShape`, `VerifySnapshotReadable`,
  `SelfSufficient`, `ErrPublishedLegacyShape`; checkpoint capture through 4 KiB buffers.
- **Graph core and CSR:** directed-multigraph `AdjList`; `BuildSymmetric`,
  `BuildSymmetricFromAdjList`, `KnownSymmetric`; `graph.(*Mapper).AppendIDs` and
  `graph.MapperCursor` for batched id walks.
- **Search and centrality:** `DiameterCtx` uses BoundingDiameters; `PageRankBudget`; pooled
  PageRank scratch vector.
- **Cypher:** `ErrParallelEdgeInSimpleGraph` removed; undirected-storage code paths removed; a Go
  API edge no longer takes a Cypher sibling's type (`4e9c48bb`); read-path, aggregation and
  relationship-materialisation allocations reduced; the constraint registry lock is skipped for
  unconstrained keys.
- **LPG engine:** an edge-property append never rewrites a cell a pinned reader can see
  (`ce609ce6`); per-`ReadView` slot index for a high-degree source; shared edge-property append
  buffers; read-locked check before version reclaim; empty shards skipped when collecting index
  suspects.
- **Interchange and tools:** GraphML and DOT always directed; `graph/io/csv`, `store/bulk`,
  `store/bulkimport` and `gograph-import` lose their direction and multigraph options.
- **Internal and tooling (not part of the module):** every example stores directed multigraphs;
  example 20 shares a PageRank budget; the example 37 IX11 ladder check now observes real
  commit/read overlap (`5b3d50af`); tests close every WAL writer in `t.Cleanup`; three test gates
  fixed at sprint close (`3e6c7024`, `bbbee294`, `7b2fd112`).

## On-disk format and upgrade

Verified against `store/snapshot/manifest.go` and `store/recovery/` at `e91d42b2`, and against
`store/snapshot/manifest.go` at `v0.16.0`.

- **The WAL format is unchanged.** No non-test file under `store/wal/` changed in this window.
- **Snapshot manifests.** `snapshot.ManifestVersion` is 5. The loader accepts versions 1 to 5,
  so every manifest written by `v0.16.0` (version 4) or earlier still loads. Every manifest this
  build writes is stamped 5, including CSR-only and mapper-less ones. `v0.16.0` has
  `ManifestVersion = 4` and refuses any higher version with `snapshot.ErrManifestUnsupported`.
- **A directed multigraph store from `v0.16.0`** (manifest `graph_config` with
  `"directed": true` and `"multigraph": true`) opens without migration. The first checkpoint
  this build takes writes a version-5 manifest; from then on `v0.16.0` refuses the directory.
- **An undirected or simple store from `v0.16.0`** (manifest `graph_config` with
  `"directed": false` or `"multigraph": false`) is migrated by the first clean recovery:
  - The WAL above the snapshot is replayed with the old engine's semantics.
  - Undirected: each edge is folded to one relationship oriented from the lower node id to the
    higher; a self-loop is kept once. When the two directions hold different values for one
    property key, or different relationship types, recovery returns an error wrapping
    `recovery.ErrLegacyMirrorConflict` that names the edges, and leaves the directory unchanged.
  - Simple: each duplicate insertion the old engine skipped is skipped again, and its edge handle
    stays reserved.
  - Before `Open` returns, a current-format snapshot is published and the WAL is folded under it.
    This needs write access, the operating-system filesystem
    (`recovery.ErrLegacyMigrationUnsupportedFS` otherwise) and a non-nil `Options.Codec`
    (`recovery.ErrLegacyMigrationNeedsCodec` otherwise). An unclean recovery rewrites nothing. A
    crash during the rewrite leaves either the legacy store, which the next open migrates again,
    or the migrated one.
- **A store with no snapshot is not migrated.** The legacy shape is read only from
  `snapshot/manifest.json`. A store directory without one records no shape, so recovery replays
  its WAL with directed-multigraph semantics.
- **Downgrade.** A migrated store, and any store after its first checkpoint by this build, cannot
  be opened by `v0.16.0`. Copy the store directory before the first open if a downgrade must
  remain possible.

## Migration

### Code changes

| Before (`v0.16.0`) | After (`v0.17.0`) | What to do |
|---|---|---|
| `adjlist.Config{Directed: true, Multigraph: true}` | `adjlist.Config{}` | Delete both fields; every graph is a directed multigraph. |
| `csv.Options`, `bulk.Options`, `bulkimport.Options` with `Directed` / `Multigraph`; `csrfile.FixtureSpec.Multigraph` | fields removed | Delete them from every literal. |
| `snapshot.GraphConfig.Directed` / `.Multigraph` | fields removed | Delete them; the decoder still reads the legacy keys for migration. |
| `(*AdjList).Directed()` / `.Multigraph()` | removed | Remove the call; both would always be true. |
| `adjlist.Writer.AppendEdge` returning `(bool, error)` | returns `error` | Drop the boolean; it reported a simple graph's skipped duplicate. |
| `errors.Is(err, cypher.ErrParallelEdgeInSimpleGraph)` | removed | Remove the branch; every `CREATE` adds a relationship. |
| `gograph-import -undirected` / `-simple` | flags removed | Remove them from every invocation. |
| Undirected analytics over an undirected `AdjList` | — | Build the CSR and call `BuildSymmetric()`, or call `csr.BuildSymmetricFromAdjList(adj)`. |
| Repeated `AddEdge` relied on to de-duplicate | adds a parallel edge | Do not repeat the insertion. |

### Behaviour changes you can observe

- A repeated `AddEdge` between the same ordered pair adds a parallel edge.
- Cypher `CREATE` refuses an undirected relationship; `MERGE` with an undirected pattern matches
  either direction and, when none exists, creates one relationship from the first node to the
  second.
- GraphML input declared `edgedefault="undirected"` loads as directed relationships from `source`
  to `target`.
- `csr.(*CSR).BuildReverse` returns the receiver itself for a known-symmetric CSR.

## Compliance mandates

- **openCypher TCK:** `tckExecutionBaseline` is 3 897 and no feature file changed. The execution
  gate runs inside `make ci`'s `test-short` stage.
- **ACID:** the legacy migration publishes its snapshot by an atomic directory swap and reclaims
  WAL segments only after it, so a crash leaves either the legacy or the migrated store. The
  edge-property append fix (`ce609ce6`) removes a data race a pinned reader could observe after a
  rollback.
- **Concurrency and efficiency:** see [Performance](#performance). `PageRankBudget` bounds the
  workers concurrent PageRank calls start.
- **Security:** no toolchain or dependency change; `go.mod` and `go.sum` are unchanged from
  `v0.16.0`.
