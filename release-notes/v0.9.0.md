# Release Notes — GoGraph v0.9.0

**Date:** 2026-07-19
**Tag:** `v0.9.0`
**Module:** `github.com/FlavioCFOliveira/GoGraph`
**Status:** Pre-1.0 (unstable public API)

---

## Overview

GoGraph v0.9.0 is the twelfth published release of GoGraph, a Go module for
graph **persistence**, **manipulation**, and — above all — **fast search**,
designed to scale from in-memory graphs to graphs that exceed RAM.

This is a pre-1.0 **MINOR** release with three complementary themes:

- **A columnar Cypher read path.** The common `MATCH (n) WHERE <predicate>
  RETURN <scalar properties>` shape is now driven **column-major** through a
  new `Chunk` batch type, boxing values to `expr.Value` only at the sink.
  End-to-end this cuts `BenchmarkEngReadProject` from **5 309 to 89
  allocations per operation**, and a query planner change makes the engine
  prefer this de-boxed chain over the boxed morsel-parallel scan.
- **Two net-new, backward-compatible Cypher clauses.** The **`FOREACH`**
  updating clause and **`SHOW CONSTRAINTS` / `SHOW INDEXES`** schema
  introspection (with a `YIELD` / `WHERE` / `RETURN` projection tail) close
  two long-standing gaps against the Cypher clients and migration tools that
  emit them.
- **A broad correctness and hardening pass.** A cluster of Cypher
  write-path and parallel-relationship fixes, a B-tree corruption fix, and a
  two-cycle whole-module production-readiness review that found no critical
  or high-severity defect.

## Semantic-versioning rationale

The bump is **MINOR** under [Semantic Versioning](https://semver.org/). The
`FOREACH` clause, the `SHOW CONSTRAINTS` / `SHOW INDEXES` introspection
commands, and the additive `cypher/exec` columnar types (`Chunk`,
`ColumnarFilter`, `ColumnarProject`, `LabelCountScan`, and their supporting
interfaces) are net-new, backward-compatible surface; every other change is
an internal correctness fix, a performance improvement, a security or
denial-of-service hardening, or test and documentation work. The **57
commits** landed since `v0.8.1` were surveyed (`git log --no-merges
v0.8.1..HEAD`, a linear history with no merge commits) and **no breaking
change to the documented public-API surface** (`graph/*`, `search/*`,
`store/*`, `ds`, `bench/*` — see [docs/semver.md](../docs/semver.md)) was
found.

One dead, never-wired exported operator — `cypher/exec.ParallelScan`, with
its `NewParallelScan` constructor and `Init` / `Next` / `Close` methods —
was **removed** (see [Removed](#removed)). It sits in `cypher/exec`, which is
outside `internal/` but is not part of the enumerated public-API surface in
`docs/semver.md`; regardless, pre-1.0 the minor digit absorbs a breaking
change to an exported identifier, so this remains a MINOR release. It is
called out explicitly below in the interest of full disclosure. As a
`0.y.z` release the public API nonetheless remains unstable: it may change
without a major-version bump while the module matures toward `1.0.0`. **Pin
the exact version you depend on.**

## Highlights

- **Columnar read path (`#1704` P1–P3).** A `RETURN n.key` projection over a
  filtered node scan is driven column-major and boxes to `expr.Value` only
  at the sink. `BenchmarkEngReadProject` drops from **5 309 to 89
  allocs/op** and from **≈ 234 µs to ≈ 53.8 µs** per query, past the "low
  hundreds" target into double digits. Correctness is byte-identical to the
  row path by construction.
- **Planner prefers the columnar chain (`#2065`).** For the filtered
  scalar-projection shape the planner now tries the de-boxed columnar chain
  before the boxed morsel-parallel scan, which ran serial-but-boxed under
  the concurrency governor. The same query drops from **182 559 to 118
  allocs/op** and **6.08 ms to 1.94 ms** under concurrency (≈ 1 550× fewer
  allocations, 2–3× faster), with no single-query regression.
- **`FOREACH` updating clause (`#2029`).** `FOREACH (x IN list | <updating
  clauses>)` binds `x` to each list element and runs `CREATE` / `MERGE` /
  `SET` / `REMOVE` / `DELETE` (and nested `FOREACH`) as side-effects,
  preserving the surrounding query's row cardinality.
- **`SHOW CONSTRAINTS` / `SHOW INDEXES` schema introspection (`#2044`).**
  Both commands (and their singular aliases) list the registered schema in
  the openCypher column order, and accept a trailing `YIELD` / `WHERE` /
  `RETURN` projection so modern clients can select, filter, and rename the
  yielded columns.
- **Exact cross-type integer/float equality (`#2050`).** Equality, grouping,
  `DISTINCT`, and hash joins compare an integer and a float **exactly**
  (per openCypher CIP2016-06-14) rather than by lossy `float64` promotion.
- **Broad Cypher write-path and parallel-relationship correctness.** A
  cluster of `MERGE`, whole-entity `SET`, and parallel-edge fixes, plus a
  string-literal round-trip corruption fix and a `setItem` disambiguation
  that stops a `WITH … SET var = <map>` panic.
- **B-tree corruption fix (`a0a5be6`).** `contains` recurses and
  `removeChild` escalation re-roots correctly, stopping a height ≥ 4
  corruption.

## What changed

### Columnar Cypher read path

The read-path work introduces a **column-major `Chunk` batch type**
(`#1704` P1) and wires the scalar-property projection onto it in two phases:
P2 unboxes the projection itself (`BenchmarkEngReadProject` 5 309 → 3 565
allocs/op, −32.8 %), and P3 removes the upstream scan-NodeID and
`WHERE`-filter boxes to reach **89 allocs/op** end-to-end (a further
−97.5 %), with query time down to **≈ 53.8 µs**. Correctness is
byte-identical to the row path **by construction**: the column filler
classifies each value with the same functions the row-at-a-time path uses
(`decodeTemporalString` verbatim for strings, `lpgPropToExpr` for every
non-plain-scalar kind), an absent property maps to the same `expr.Null`
singleton via a validity bitmap, integers and floats are never conflated,
and `NaN` / `±Inf` bit patterns are preserved.

Two more columnar wins build on the same model: a **`WITH`-projection
passthrough** (`#2045`) drops `BenchmarkWithFilterPassthrough` from 5 324 to
118 allocs/op (−97.8 %), and **unboxed grouping-key hashing in
`EagerAggregation`** (`#2049`) drops `BenchmarkAggGroupScalar` from 15 598
to 1 889 allocs/op (−87.9 %) while preserving openCypher grouping
equivalence (`1` and `1.0` group together, `NaN` with `NaN`, `NULL` keys in
one group, and two distinct integers `≥ 2^53` that share a `float64`
bit-pattern stay in separate groups).

Finally, the **query planner prefers the columnar chain** over the
morsel-parallel scan for the eligible filtered scalar-projection shape
(`#2065`). `ParallelScanProject` still handles the shapes the columnar chain
declines (no filter, compound predicates, non-property scalar items). The
result multiset is unchanged and the openCypher TCK holds at 3 897 / 3 897.

### `FOREACH` updating clause

```cypher
-- update every node bound along a matched path
MATCH p = (a:Person {name: 'Alice'})-[:KNOWS*]->(b:Person)
FOREACH (n IN nodes(p) |
  SET n.visited = true
)
```

`FOREACH (x IN list | <updating clauses>)` binds `x` to each element of a
list and runs the body clauses as side-effects, preserving the surrounding
query's row cardinality. The body accepts `CREATE`, `MERGE`, `SET`,
`REMOVE`, `DELETE`, and a nested `FOREACH`, over a literal list, a bound
list variable, or a list-valued expression. The translator lowers it to a
correlated body sub-plan (`Argument → Unwind(list) → updating clauses`) that
`exec.Foreach` drains once per outer row for its writes, then forwards the
outer row unchanged; `positionFromNode` learns `Foreach` so a `FOREACH`
after `WITH` keeps its document order. `FOREACH` is not TCK-covered, so the
3 897 baseline is unaffected. (`#2029`)

### `SHOW CONSTRAINTS` / `SHOW INDEXES` schema introspection

```cypher
SHOW CONSTRAINTS;
SHOW INDEXES YIELD name, type WHERE type = 'RANGE' RETURN name;
```

Both commands — and the singular `SHOW CONSTRAINT` / `SHOW INDEX` aliases —
list the registered schema in the openCypher column order (`SHOW
CONSTRAINTS` yields `name, type, entityType, labelsOrTypes, properties`;
`SHOW INDEXES` yields `name, state, type, entityType, labelsOrTypes,
properties`). A trailing `YIELD` / `WHERE` / `RETURN` projection is accepted
so modern clients can select a subset of columns, filter the yielded rows,
and rename or reorder the output. (`#2044`)

### Cypher correctness

- **`MERGE` and pattern matching over parallel relationships.** `MERGE`
  fans its bindings out per pre-existing parallel relationship; `DELETE r`
  removes the exact bound parallel-edge instance; an untyped `[r]` is
  enumerated per parallel instance in `EvalPatternComp`; and a fresh
  same-pattern node reference is resolved in `MERGE` inline properties.
- **Whole-entity `SET`.** Non-literal values in whole-entity `SET n = {…}`
  maps and in `MERGE` inline relationship properties are evaluated; a
  whole-entity `SET` map is written from a bound map variable; whole-entity
  `SET` is applied in `MERGE ON CREATE` / `ON MATCH`; a `SET n = <map-
  returning expression>` is honoured; and a whole-entity `SET` that violates
  a `UNIQUE` constraint is rolled back instead of silently skipped.
- **`setItem` disambiguation.** `WITH … SET var = <map/param>` no longer
  panics; the parser distinguishes a property-set from a whole-entity map
  assignment.
- **String-literal round-trip.** Backslashes in a string literal are escaped
  on the round-trip, stopping silent property corruption.
- **`MERGE` read-own-writes on a null property.** A `MERGE` whose property
  resolves to a runtime `NULL` (including from a null parameter) raises
  `MergeReadOwnWrites` instead of proceeding.
- **`CALL … YIELD … WHERE`** applies its `WHERE` predicate to the yielded
  rows; a leading `FOREACH` no longer panics; a node/relationship-valued
  inline property is rejected; a parameter may be supplied as a whole
  property map on `CREATE`; and `CREATE INDEX` on an empty graph no longer
  pins the index key type to `String`.
- **`AND` / `OR` / `XOR` / `NOT` reject a non-boolean runtime operand** with
  a typed `TypeError` instead of silently coercing it (`NULL` operands are
  still handled by openCypher three-valued logic). (`#2059`)

### Storage, search, and I/O correctness

- **B-tree.** `contains` recurses and `removeChild` escalation re-roots
  correctly, stopping a height ≥ 4 corruption. (`a0a5be6`)
- **Search.** `TransitiveClosure.Reachable` is reflexive for in-range
  `NodeID`s; `NaN` / `Inf` is validated for defined float weight types via
  the reflect kind; and the unbounded `KShortestPathsLoopless` bare entry is
  deprecated in favour of the bounded, cancellable
  `KShortestPathsLooplessCtxWithOpts` or the polynomial `YenKShortest`.
- **I/O round-trips.** A CSV cell that begins with the comment rune is
  force-quoted so it round-trips; JSONL distinguishes an absent field from
  an empty one so an empty-string identifier round-trips.

### Security and hardening

The two-cycle whole-module production-readiness review (the 2026-07-16/17
and 2026-07-19 multi-specialist audits, recorded in
[docs/audit-production-readiness-2026-07-19.md](../docs/audit-production-readiness-2026-07-19.md))
found **no critical or high-severity defect** and certified both compliance
mandates. Its two highest-value findings were remediated in this release:
the `AND` / `OR` non-boolean coercion (above) and the columnar-first planner
reorder. In addition, the Bolt message-reassembly buffer is now charged
against the aggregate inbound budget, closing a memory-amplification gap in
the chunked-message reader (`1c9b079`). `go test -race ./...`, the
crash-injection battery, and `govulncheck ./...` are clean.

### Performance (beyond the columnar read path)

- **`count(*)` over a bare label scan** is pushed down to an O(1) index
  read. (`8134796`)
- **Lock-free tombstone read path** in `graph/lpg` restores read scaling
  under concurrency. (`95da80d`)
- **Struct field re-alignment** removes compiler padding across 33 struct
  types and trims ≈ 7.5 KB of operator allocation size and garbage-collector
  mark work. (`a5d0fe7`)
- **All-scalar Bolt `RECORD` rows** are streamed through a typed encoder
  with no per-cell boxing. (`2749809`)

### Removed

- **The dead `cypher/exec.ParallelScan` operator** (its `NewParallelScan`
  constructor and `Init` / `Next` / `Close` methods). It had no planner call
  site — the live parallel leaves are `ParallelScanProject` and
  `ParallelCountScan` — and it sized workers directly from `GOMAXPROCS`,
  bypassing the `ParallelGovernor`. No production behaviour changed. This is
  a change to an exported identifier outside `internal/`; pre-1.0 the minor
  digit absorbs it and the documented public-API surface is unaffected.
  (`#2019`)

## Upgrade notes

- **No migration required.** Stores written by earlier releases open without
  conversion. `FOREACH`, the `SHOW` introspection commands, and the columnar
  read path are additive; existing code and queries compile and behave
  unchanged.
- **Integer/float equality is now exact (behaviour change).** If your
  application relied on two distinct integers `≥ 2^53` that share a
  `float64` bit-pattern comparing or grouping as equal, they are now
  **distinct**. Values within the exactly-representable range are
  unaffected (`1 = 1.0` still holds and they still group together). This
  aligns GoGraph with openCypher CIP2016-06-14, its own `MERGE`, and Neo4j.
- **`AND` / `OR` / `XOR` / `NOT` on a non-boolean operand now errors
  (behaviour change).** A boolean operator applied to a non-boolean,
  non-null runtime value returns a typed `TypeError` instead of silently
  coercing it. A well-typed query is unaffected; `NULL` operands continue to
  follow three-valued logic.
- **`search.KShortestPathsLoopless` (bare entry) is deprecated.** Its
  behaviour is unchanged in this release, but it is a super-polynomial-blowup
  foot-gun on arbitrary input. Migrate to
  `KShortestPathsLooplessCtxWithOpts` (bounded and cancellable) or
  `YenKShortest` (polynomial).
- **`cypher/exec.ParallelScan` was removed.** If you imported this
  unexported-in-practice physical operator directly (it had no planner call
  site), switch to the live `ParallelScanProject` / `ParallelCountScan`
  leaves or the columnar operators. No query behaviour is affected.
- **Pin the exact version.** As a `0.y.z` release the public API may still
  change without a major bump.

## Benchmark evidence summary

This release's performance work is entirely in the **Cypher read path**; the
headline guard-band set (the `search` / `search/centrality` algorithms) is
not on any changed path, and its allocation columns are **identical to
`v0.8.1`** (`Dijkstra_PostWarmup` and `BFSDirectionOpt_PowerLaw` allocate
zero bytes per call; `Dijkstra_Large`, `Yen_K100`, and `Brandes_RandomGraph`
match their prior allocation footprints exactly). The read-path wins are
substantial and independently measured:

- **`BenchmarkEngReadProject`**: 5 309 → **89 allocs/op** end-to-end,
  ≈ 234 µs → ≈ 53.8 µs.
- **`BenchmarkWithFilterPassthrough`**: 5 324 → **118 allocs/op**.
- **`BenchmarkAggGroupScalar`**: 15 598 → **1 889 allocs/op**.
- **Planner columnar-first (filtered scalar projection, 60k nodes)**:
  182 559 → **118 allocs/op**, 6.08 ms → 1.94 ms under concurrency.

A read-path concurrency sweep (1/8/64/256/1024 goroutines) stays flat at
≈ 72–88 ns/op with zero allocations, confirming graceful degradation under
128× core over-subscription. The authoritative measured figures — the
headline guard-band set, the columnar read-path table, and the concurrency
sweep — are recorded in
[docs/benchmarks/v0.9.0.md](../docs/benchmarks/v0.9.0.md), measured on the
run environment documented there. Consult that document for the
per-benchmark numbers; no benchmark figure in these notes should be read as
a substitute for it.
