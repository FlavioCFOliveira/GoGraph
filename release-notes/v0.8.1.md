# Release Notes — GoGraph v0.8.1

**Date:** 2026-07-14
**Tag:** `v0.8.1`
**Module:** `github.com/FlavioCFOliveira/GoGraph`
**Status:** Pre-1.0 (unstable public API)

---

## Overview

GoGraph v0.8.1 is the eleventh published release of GoGraph, a Go module
for graph **persistence**, **manipulation**, and — above all — **fast
search**, designed to scale from in-memory graphs to graphs that exceed
RAM.

This is a pre-1.0 **PATCH** release with a single, focused module change:
it **fixes a Cypher pattern-predicate and pattern-comprehension
correctness bug** that affected graphs holding **parallel edges** — two
or more relationships of different types between the same ordered pair of
nodes. The fix is:

- **Pattern-predicate and pattern-comprehension relationship-type
  matching now considers every parallel type.** When several
  relationships of different types connected the same ordered node pair,
  the evaluator inspected only the **first** stored type, so any non-first
  type was reported as absent. Over `(a)-[:FIRST]->(b)` and
  `(a)-[:SECOND]->(b)`, the predicate `WHERE NOT (a)-[:SECOND]->()`
  wrongly kept `a`, and a bound relationship variable's `type(r)` could
  report the wrong type. The evaluator now tests every relationship type
  of the endpoint pair, across the outgoing, incoming, undirected,
  variable-length, and comprehension paths. (#2016)

It is **API-additive** over `v0.8.0`: no exported identifier was added,
removed, or renamed, there is **no breaking change**, and there is **no
new user-facing public API**. It is a **recommended upgrade** for anyone
who runs pattern predicates, pattern comprehensions, or binds a
relationship variable over a multigraph.

## Semantic-versioning rationale

The bump is **PATCH** under [Semantic Versioning](https://semver.org/).
The only production-source change is a backward-compatible **bug fix** in
the Cypher pattern evaluator (`cypher/pattern_eval.go`); it corrects
wrong query results and introduces no new surface. The other changes in
the release are release-engineering and continuous-integration
consolidation, a soak-layer test-compilation repair, a
coverage-instrumentation test skip, and documentation maintenance — none
of which touches the module's public API. As a `0.y.z` release the public
API nonetheless remains unstable: it may change without a major-version
bump while the module matures toward `1.0.0`. **Pin the exact version you
depend on.**

## What changed

### Fixed — pattern-predicate relationship-type matching over parallel edges

Consider a graph with two differently-typed relationships between the
same ordered pair of nodes:

```cypher
CREATE (a:N {k: 1})-[:FIRST]->(b:N {k: 2});
MATCH (a:N {k: 1}), (b:N {k: 2}) CREATE (a)-[:SECOND]->(b);

// Before v0.8.1 this WRONGLY returned a (it judged the :SECOND edge absent):
MATCH (a:N {k: 1}) WHERE NOT (a)-[:SECOND]->() RETURN a;   // now returns no rows

// A bound relationship variable now reports the pattern-selected type:
MATCH (a)-[r:SECOND]->(b) RETURN type(r);                  // now "SECOND"
```

The pattern evaluator resolved a relationship type from the endpoint pair
via `EdgeLabels(pair)[0]` — only the **first** stored type — so a
parallel type that was not stored first was reported as non-existent, and
`type(r)` on the pattern-comprehension fallback path could report the
first-stored type rather than the one the pattern selected. The
single-relationship chokepoint `edgeMatchesRel` now tests **every** type
of the endpoint pair, which fixes the outgoing, incoming, undirected,
variable-length, and comprehension paths through one code path, and
`relValueFromHop` reuses the canonical `pickEdgeType` resolver so
`type(r)` reports the pattern-selected type. Three regression tests guard
the fix (`cypher/rel_multitype_pattern_test.go`), each verified red
without the change and green with it. (#2016)

### Changed — release engineering and continuous integration

- **CI consolidated to a single release workflow, with all correctness
  gating enforced locally.** The GitHub Actions surface is reduced to
  `release.yml` (tag-triggered publish plus the fast release-accuracy
  check); the correctness, coverage, TCK-execution, and crash-injection
  gates now run only locally through `make ci` / `make release-preflight`
  before a tag is pushed.
- **The local release gate was de-duplicated so the race-enabled,
  coverage-instrumented suite runs once.** `make release-preflight` is now
  `release-accuracy` + `make ci` + the headline benchmark;
  `scripts/pre-release.sh` is a standalone, no-coverage convenience gate
  rather than a redundant second full run.

### Testing

- **Soak-layer test compilation repaired** after the `PropsEvalFn`
  error-return and `btree.RangeFrom` additions from `v0.8.0`, so the
  `soak` build tag compiles cleanly.
- **PackStream allocation-charge upper-bound test** is skipped under
  coverage instrumentation, where the coverage counters perturb the
  measured allocation budget; the assertion still runs in the normal and
  `-race` passes.
- **Release-path guard reconciled with the de-duplicated gate.** The
  `TestReleasePathsConverge` release-integrity check
  (`internal/scriptgate`) had still asserted the pre-de-duplication path
  (`release-preflight` → `scripts/pre-release.sh`). It now enforces the same
  anti-bypass invariant against the current pipeline —
  `release` → `release-preflight` → `make ci` — after the correctness gate
  moved out of `scripts/pre-release.sh` and into `make ci`.

## Upgrade notes

- **No migration required.** Stores written by earlier releases open
  without conversion. The fix changes only query evaluation, not the
  on-disk format or any API.
- **Query results over parallel edges may change (bug fix).** If your
  application depended on the previous, incorrect behaviour — where a
  pattern predicate or a bound relationship variable ignored all but the
  first-stored type between a node pair — results now correctly reflect
  every parallel relationship type. This affects only multigraphs that
  carry more than one relationship type between the same ordered pair of
  nodes.
- **Pin the exact version.** As a `0.y.z` release the public API may
  still change without a major bump.

## Benchmark evidence summary

This release contains **no performance work**. The sole production-source
change (`cypher/pattern_eval.go`) is on the Cypher pattern-evaluation
path, not on any benchmarked hot path — verifiable with
`git diff --numstat v0.8.0..v0.8.1 -- '*.go' | grep -v _test.go`, which
lists that one file only. Because the code on every benchmarked path is
byte-identical to `v0.8.0`, the headline guard-band figures are
**inherited unchanged from `v0.8.0`**; the two post-warmup traversal
paths continue to allocate **zero** bytes per call. The per-benchmark
numbers, the run environment, and the change-set proof are recorded in
[docs/benchmarks/v0.8.1.md](../docs/benchmarks/v0.8.1.md).
