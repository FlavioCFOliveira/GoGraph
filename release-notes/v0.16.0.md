# Release Notes — GoGraph v0.16.0

**Release date:** 2026-10-09 (pending the tag)
**Tag:** `v0.16.0`
**Previous release:** [`v0.15.0`](v0.15.0.md) (2026-09-17)
**Module path:** `github.com/FlavioCFOliveira/GoGraph`
**Go toolchain:** `go.mod` pins `go 1.26` and `toolchain go1.27.0`.
`git diff v0.15.0..60c90d73 -- go.mod go.sum` is empty: no dependency moved in this window.

## Read this first

**`v0.16.0` changes the on-disk format and breaks the exported API.**

1. **WAL v2 is a one-way migration.** The first writable, clean open of a store written by an
   earlier release seals its single-file WAL and continues in a segmented log. From that moment
   **`v0.15.0` and every earlier build refuse the directory.** The first checkpoint then writes a
   version-4 snapshot manifest, which `v0.15.0` also refuses. Copy the store directory before the
   first open with `v0.16.0` if you need to keep a downgrade path.
2. **71 exported declarations changed signature incompatibly and 4 were removed.** Most mutators of
   `graph/lpg`, `graph/adjlist` and `cypher/exec.GraphMutator` now return the refusal as an
   `error`. See [Migration](#migration).
3. **A direct write is now a single-operation transaction.** It can be refused with
   `lpg.ErrDirectWriteConflict`, and it is never part of an exclusive bracket. Code that relied on
   a direct call joining `ApplyAtomically` must write through `Graph.Writer(tx)`.

## Semantic-versioning classification

The version `v0.16.0` was set by the user. Under [docs/semver.md](../docs/semver.md), a `0.y.z`
release absorbs breaking changes in the MINOR digit, so a MINOR bump is the conventional class for
this content. The classification evidence: the exported surface was diffed by parsing every
non-test Go file outside `internal/`, `examples/`, `cmd/` and any `gen/`, `tck/` or `testdata/`
directory at `v0.15.0` and at `60c90d73` — a superset of the policy's API surface. The result is
74 re-signings (two are parameter renames, one widens a parameter to an interface the old type
satisfies), 4 removals and 342 additions, plus an incompatible on-disk format change. After
`1.0.0` the same content would require a MAJOR release.

## Highlights

### WAL v2: segments, prev-link, store id, id annex, id reservations

The design is [docs/design-wal-v2.md](../docs/design-wal-v2.md); the byte format is
[store/wal/FORMAT.md](../store/wal/FORMAT.md).

- **Layout.** `wal.control` (64 bytes, a random per-store id, the oldest retained position and the
  checkpoint redo position), numbered 16 MiB segments under `wal.d/`, and the legacy `wal` file,
  which after migration ends in a seal.
- **Frames.** A 36-byte header carries the frame's logical position, the distance back to its
  predecessor and the store id. Recovery refuses a foreign store, a misplaced frame, a broken
  prev-link, a segment gap, a torn non-tail segment, and a snapshot too old for or ahead of the
  log — each with its own error.
- **Reclamation.** A checkpoint unlinks whole segments below the oldest retained position,
  without the commit lock. `wal.Writer.TruncatePrefix` is gone.
- **Node-id stability.** Every commit marker names the node ids its transaction created, and
  recovery places them before replaying operations, so `id()` and `elementId()` no longer move
  across a reopen. Ids are issued only below a per-shard limit logged ahead of use in a
  `ReserveIDs` control record, and checkpoints persist the per-shard marks in `nodeids.bin`.
- **Clean close.** The new `store/txn.(*Store).Close` appends the exact per-shard marks, so a clean
  restart wastes no id. `store.Opened` calls it for you under the commit lock.
- **Truncated log without its snapshot.** A durable `wal.prefix-truncated` marker makes recovery
  refuse such a directory with `recovery.ErrMissingSnapshot` instead of opening it empty.

### One composed, fail-safe open

`store.Open` / `store.OpenCtx` run recovery, the clean gate, the WAL open and the store
construction in one call, and return a `*store.Opened` that cannot drop the recovered sequence,
codecs or schema. An unclean recovery is refused with `store.ErrUncleanRecovery`; with
`Options.AllowUnclean` the directory opens read-only and every write fails with
`store.ErrReadOnlyStore`. `cypher.NewEngineWithOpened` builds an engine over it.

### Every write path is atomic and isolated

A direct mutator call is an implicit transaction: it conflict-tests, commits at one instant, and
on a refusal changes nothing. A durable store commit is applied as an uncommitted transaction
first, then logged and fsynced, then published, so it is refused before its WAL record, never
after it. A waiting write parks on the conflicting commit instead of polling: at 32 committers on
one node, commit p99 went from 1.000 s to 136 ms with zero refusals (measured by the shipping
task). Direct reads return the newest committed state.

### One token limit on every layer

A label, relationship type or property key longer than 65 535 bytes (`lpg.MaxTokenLen`) is refused
with `lpg.ErrTokenTooLong` before any state change, by the in-memory engine, the WAL-backed store,
bulk import and both Cypher engines. Before, only the WAL refused it, and a WAL-backed store
acknowledged an over-long relationship type and recovered it with no type.

### Cypher

- `UNION` and `UNION ALL` inside `EXISTS { }` and `COUNT { }`.
- `PROFILE` of writing statements.
- An index seek is kept for absent values and for a sole-leaf seek on a property the statement
  writes (see [Performance](#performance)).
- Correctness fixes across rollback, pattern predicates, variable-length paths,
  parsing, write-clause maps, `MERGE` under `UNIQUE`, counters and cancellation, listed in the
  [CHANGELOG](../CHANGELOG.md).

## Changes by area

The complete, per-commit list is the `## [0.16.0]` entry of [CHANGELOG.md](../CHANGELOG.md). This
section groups it.

- **Storage and recovery:** WAL v2; id annex and reservations; snapshot manifest v4 with
  `nodeids.bin`; never-born ids as holes; prefix-truncation marker; byte-reproducible snapshot,
  JSONL and GraphML output; bulk-import directory fsyncs and `PublishFS`/`ImportIntoFS`;
  `store.Open`, read-only unclean open, `Store.Close`.
- **MVCC and the LPG engine:** implicit single-operation transactions for direct and raw writes;
  apply-before-log store commits; parked waiters; committed-state direct reads; abort restores
  adjacency pre-images; WAL order equals publication order; no-op writes take no stamps and log
  nothing; node-life, label-index and constraint consistency under churn and abort.
- **Cypher:** the fixes and features above; fail-stop sentinel `cypher.ErrEngineFailStopped`.
- **Indexes:** commit-time delivery is fail-stop (`index.ErrIndexStateUndefined`); index state is
  read at the reader's snapshot; a raw write under a registered index is refused
  (`lpg.ErrIndexedRawWrite`).
- **Bolt:** `ErrFieldTooLong` split by field kind, each with its own code; the over-long
  relationship type maps to `Neo.ClientError.Schema.TokenLengthError`; `Server.Transactions` is
  n log n.
- **Observability:** metric shards reach every shard under `-race`; `MVCCStats` gains
  `HelpedPublications` and `OutOfOrderPublications`; `NodeLifeRecords` no longer over-reports.
- **Internal and tooling (not part of the module):** example 37's MVCC scenario catalogue, ladder,
  crash-durability phase and Hermitage goldens; seeded fsync latency injection; harness child
  binaries built on disk outside the RAM-drive temp area; a NodeID-stability oracle in the
  simulator.

## Migration

### Before the first open

- Back up the store directory if a downgrade to `v0.15.0` must remain possible. Migration happens
  on the first writable, clean open; a read-only (`AllowUnclean`) open writes nothing.
- Close stores cleanly: call `store.Opened`'s close, or `txn.Store.Close` before closing the WAL
  when you compose the store by hand.

### Code changes

| Before (`v0.15.0`) | After (`v0.16.0`) | What to do |
|---|---|---|
| `g.RemoveEdge(a, b)` and the other `graph/lpg`, `graph/adjlist` mutators listed in the CHANGELOG | return `error`, `(bool, error)` or `(int, error)` | Handle the error. A refusal wrapping `mvcc.ErrSerializationConflict` or `lpg.ErrDirectWriteConflict` is retryable. |
| Implementations of `graph.Graph` or `cypher/exec.GraphMutator` | interface methods return `error` | Update the implementation's signatures. |
| `LabelRegistry.Intern`, `PropertyKeyRegistry.Intern`, `schema.Schema.RegisterLabel` | return `(id, error)` | Handle `lpg.ErrTokenTooLong`; validate up front with `lpg.CheckToken`. |
| `mapper.LoadFrom(entries)` | `mapper.LoadFrom(entries, next)` | Pass the per-shard marks, or `nil`. |
| `ast.ExistsSubquery.Query` / `ast.CountSubquery.Query` of type `*ast.SingleQuery` | type `ast.Query` | Use `ast.QueryBranches(q)` to walk the branches. |
| `wal.Writer.TruncatePrefix`, `wal.ErrPrefixTruncateUnsupported` | removed | Let a checkpoint reclaim segments. |
| `recovery.Result.WALTailOffset` | removed | Use `WALEnd`, `WALLastFramePos`, `WALTailSegment`, `WALTailSegmentOffset`. |
| `snapshot.ErrCaptureNotQuiesced` | removed | Nothing: the capture is no longer refused. |
| A direct mutator call inside `ApplyAtomically` relied on to join the bracket | the call is its own transaction | Write through `Graph.Writer(tx)` inside `ApplyAtomicallyTx` or `ApplyInsideLockedTx`. |
| `txn.ErrCommittedNotApplied` checks | never returned (deprecated) | Remove the branch; handle the retryable conflict instead. |

### Behaviour changes you can observe

- Two transactions writing properties or types on relationships out of the same node now
  conflict; the second receives a retryable serialization conflict.
- A store commit on a node another commit is writing waits for that commit's fsync.
- A WAL records effects only: a no-op operation writes no frame, and a commit in which nothing took
  effect writes nothing and mints no sequence.
