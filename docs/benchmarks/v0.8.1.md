# Benchmarks — v0.8.1

Headline benchmark and load-test numbers for the GoGraph **v0.8.1**
release.

> **Figures inherited from `v0.8.0`.** v0.8.1 is a **correctness-only
> PATCH**: its sole production-source change fixes a Cypher
> pattern-predicate and pattern-comprehension relationship-type match
> over parallel edges (`cypher/pattern_eval.go`) and **does not alter any
> hot path**. This is verifiable: `git diff --numstat v0.8.0..v0.8.1`
> reports exactly **one** non-test `.go` file changed —
> `cypher/pattern_eval.go` — and it is on the Cypher pattern-evaluation
> path, not on any benchmarked path (`search/dijkstra.go`,
> `search/bfs_do.go`, `search/yen.go`, `search/centrality/brandes.go`,
> `graph/mapper.go`, or the `cypher/exec` pipeline operators). Because the
> code on every benchmarked path is byte-identical between the two tags, a
> fresh benchstat comparison would show `~` (no significant change) on
> every row by construction; running one would only add cross-session
> measurement noise. The numbers below are therefore carried forward
> **verbatim from [v0.8.0](v0.8.0.md)**, which remains the authoritative
> measured baseline for every reported path. See
> [release-notes/v0.8.1.md](../../release-notes/v0.8.1.md) for the full
> release narrative.

> Re-measure on your own hardware before relying on any absolute
> number; these are medians from documented runs, not a guarantee.

query forms.

## Performance impact of this release

**None intended, none possible on a benchmarked path.** The single
production-source change (`cypher/pattern_eval.go`) makes the
pattern-predicate and pattern-comprehension evaluator test every
relationship type of a parallel-edge endpoint pair — previously it
inspected only the first-stored type. It executes only when a query uses
a pattern predicate, a pattern comprehension, or binds a relationship
variable, and it is not exercised by any benchmark in the headline
guard-band set (`search`, `search/centrality`) or by the `cypher/exec`
pipeline-operator benchmarks. The remaining changes in the release are
CI/release-tooling, test-compilation, and documentation work with no
runtime footprint. The guard-band figures are therefore identical to
`v0.8.0` and there is **no regression**.

## Load test — read-path concurrency sweep

CLAUDE.md requires a load-test report "at multiple concurrency levels
(1, 8, 64, 256, 1024 goroutines)". As in
[v0.8.0](v0.8.0.md#load-test--read-path-concurrency-sweep), we sweep
`GOMAXPROCS` over the `b.RunParallel` hot-key intern benchmark — the
tightest shared-state contention point in the read path, where every
goroutine interns the **same** key and competes for the same cache line.
The read path (`graph/mapper.go`) is unchanged in `v0.8.1`, so the
figures are inherited. Each figure is the median of 5 samples.

| Goroutines (`GOMAXPROCS`) | ns/op (median) | B/op | allocs/op |
|--------------------------:|---------------:|-----:|----------:|
| 1 | 7.70 | 0 | 0 |
| 8 | 95.11 | 0 | 0 |
| 64 | 90.68 | 0 | 0 |
| 256 | 90.05 | 0 | 0 |
| 1024 | 89.15 | 0 | 0 |

**Reading the sweep.** From 8 to 1024 goroutines (a 128×
over-subscription of the 10 physical cores) per-op latency stays **flat
at ≈ 89–95 ns/op with zero allocations** — the structure degrades
gracefully and predictably under massive over-subscription rather than
collapsing, so the bounded-resource and lock-contention mandates hold.

## Reproduce

The same commands that produced the inherited `v0.8.0` figures:

```
# Headline / guard-band set (median of 6)
./scripts/run_headline_bench.sh

# Read-path concurrency sweep (median of 5)
go test -run='^$' -bench='^BenchmarkMapper_Intern_HotKey_Parallel$' \
  -benchmem -cpu=1,8,64,256,1024 -count=5 ./graph/
```

To confirm no benchmarked path changed between the two tags:

```
git diff --numstat v0.8.0..v0.8.1 -- '*.go' | grep -v '_test.go'
# -> 31  10  cypher/pattern_eval.go   (the only non-test source change)
```

Per-change (rather than per-release) tracking lives in
[`history/`](history/) via
[`scripts/bench-history.sh`](../../scripts/bench-history.sh); the
narrative ledger is [`history/LEDGER.md`](history/LEDGER.md). The
authoritative measured baseline for every path above is
[v0.8.0](v0.8.0.md).
