# Benchmark Record — GoGraph v0.17.0

This is the per-release benchmark record that `internal/docscheck`
(`TestPerReleaseBenchmarkReportExists`, rmp #1398) requires for every release.

## Scope

**No release-time benchmark campaign was run for `v0.17.0`.** Benchmark execution is not part
of the release path (see [docs/release.md](../release.md)). Every figure below is either a
development-time measurement recorded in the body of the commit that shipped the change, against
that commit's own control, or a sweep total recorded in the sprint 367 laboratory report. The
rows measure different workloads, are **not additive**, and **no whole-release delta is
claimed**.

**No load test at the published 1, 8, 64, 256 and 1 024 goroutine concurrency levels was run for
this release.**

## Costs recorded

- `e7b12a60`: `BuildSymmetricFromAdjList` is +27.09 % sec/op against
  `BuildFromAdjList(adj).BuildSymmetric()`; it trades CPU for memory.
- `6b399a3b`: BoundingDiameters is +203 % on a 600-vertex cycle; vertex-transitive shapes need one
  sweep per vertex, and the O(n(n+m)) worst case is unchanged.
- `d56bfbe6`: B/op +0.02 % on the Go API relationship projection.

## Not measured for this release

- The legacy-store migration (fold and checkpoint) against an open of a current-format store.
- The directed-multigraph storage change against `v0.16.0` on the same workload.
- The concurrency ladder (1, 8, 64, 256, 1 024 goroutines).
