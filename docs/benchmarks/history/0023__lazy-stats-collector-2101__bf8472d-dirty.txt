# Lazy statistics collector — zero write-path regression when statistics are
# unused (sprint 308 #2101). The planner statistics landed on main @52e317e/
# @bf8472d and left a small UNCONDITIONAL write regression on the autocommit
# write path even though a stats-free workload never populates a collector.
#
# Root cause (measured, NOT the Tracking() atomic — CREATE (:N) writes no
# property so that hook is never reached): the `stats *statsCollector` FIELD
# pushed two per-statement heap structs across a malloc size class:
#   lpgMutatorAdapter  64 B -> 72 B  (size class 64 -> 80)  = +16 B/op
#   lpgLabelResolver   16 B -> 24 B  (size class 16 -> 24)  = +8  B/op
# A lazy collector alone does NOT recover this (the field remains). The fix
# folds the two engine-derived pointers (cs + stats) into ONE `eng *Engine`
# back-pointer on both mutator adapters and the label resolver, restoring the
# pre-statistics 8-field/64-B and 2-field/16-B layouts, AND makes the collector
# lazy (atomic.Pointer, allocated only on the first RefreshStatistics).
#
# Measurement: BenchmarkEngWriteAutocommit (bench/mtaudit), Apple M4, go1.26.5,
# -benchmem -count=10. Baseline = 17eb8dc (pre-statistics). Regressed = bf8472d
# (statistics as shipped). Fix = bf8472d + #2101 (this dirty tree).
