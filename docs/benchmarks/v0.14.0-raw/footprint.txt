STORAGE / MEMORY FOOTPRINT — graph/index/count BenchmarkStoreFootprint
================================================================================================================
v0.13.0's report (§5.6) recorded footprint as UNMEASURED: the benchmark was NEW in
v0.13.0 and had no v0.12.0 counterpart. It exists in BOTH trees now, so that named gap
is closed here.

The strongest evidence is the BUILD, not a number. The graph/index/count test binary is
byte-identical across all three arms:
  b4ad4b3357f20fb24cade83bbf8a0fe18f46ff5e54806503d95530e6ee8ac5df   (A == B == B2)
The code under this benchmark did not change between v0.13.0 and v0.14.0, so its
footprint cannot have changed. The interleaved run below is a consistency check on
that, and doubles as a third same-code floor.

CAVEAT ON THE METRIC. `B/store` is computed from runtime.MemStats, which is
PROCESS-GLOBAL, divided by b.N. Under -test.cpu=1,8,64,256,1024 b.N changes, so the
same binary reports 49984 / 107328 / 566080 / 2138945 / 8430413 B/store across the five
levels. Those are one footprint over five different denominators, NOT five footprints.
The figures below are therefore taken at the DEFAULT GOMAXPROCS only.
