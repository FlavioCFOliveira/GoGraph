# Benchmarks — v0.8.0

Headline benchmark and load-test numbers for the GoGraph **v0.8.0**
release. v0.8.0 is a **correctness and security hardening** release: it
contains **no performance-focused work** beyond one targeted
micro-optimisation of the commit-time `NOT NULL` existence check
(#1911). Its purpose here is therefore a **regression check** — evidence
that the schema-DDL, recovery-reader, Bolt, and Cypher-correctness fixes
did not regress any hot path — rather than a headline performance story.
Per-change performance records live in [`history/`](history/) and
[`history/LEDGER.md`](history/LEDGER.md).

The figures below were re-measured for this release with
[`scripts/run_headline_bench.sh`](../../scripts/run_headline_bench.sh)
(`-count=6`, median reported) and the read-path concurrency sweep
(`-count=5`, median reported). They are the authoritative per-release
performance picture for v0.8.0.

> Re-measure on your own hardware before relying on any absolute
> number; these are medians from documented runs, not a guarantee.

## Performance impact of this release

This release's headline is correctness and security hardening, not a
performance-audit cycle. Exactly one performance change lands:

1. **The commit-time `NOT NULL` existence check is O(1) and
   allocation-free** (#1911). A copy-on-write `label → NOT-NULL-
   properties` index replaces a per-node locked full-map scan plus a
   fresh slice allocation on every committed node. The targeted
   `BenchmarkNotNullProperties` over 257 constraints reports **6.3 ns/op,
   0 B/op, 0 allocs/op**. This benchmark is specific to the constraint
   commit path and is not part of the search/centrality guard-band set,
   so it does not appear in the comparison table below; it is a new
   micro-benchmark added alongside the fix with no `v0.7.0` baseline to
   diff against like-for-like.

Every other change this cycle — the `FOR ... REQUIRE` constraint grammar,
the schema-DDL durability/atomicity fixes, the Cypher-correctness fixes,
and the security/DoS hardening (value-depth caps, bounded recovery
readers, Bolt auth) — is invoked only on its respective code path and
does not touch the `Dijkstra`/`BFS`/`Yen`/`Brandes` traversal hot loops
or the `cypher/exec` pipeline operators, confirmed by the
[measured comparison](#v070--v080-comparison) below.

## v0.7.0 → v0.8.0 comparison

This section is a **real, measured** side-by-side benchmark of the
`v0.7.0` tag (commit `bb3ad3a`) against this release's `HEAD`
(`d9a915e`). Both sides were built and run on the same machine, in the
same session, with the **same benchmark binaries' names** and the
**same Go toolchain** (`GOTOOLCHAIN=go1.26.5` forced on both, so the
delta is code-only and not confounded by the `go1.26.4 → go1.26.5`
toolchain bump this release also lands): the `v0.7.0` tree was checked
out into a throwaway `git worktree` (`git worktree add --detach v0.7.0`),
each benchmark set was run with `go test -bench -benchmem -count=6`
**sequentially — never concurrently with anything else** — on both
trees, and the two sample sets were compared with `benchstat` (`old` =
`v0.7.0`, `new` = `v0.8.0`). The worktree was removed afterwards.

> **Methodology note.** An initial attempt at this comparison ran while
> the orchestrating session was issuing unrelated shell commands
> (`grep`, `git status`) on the same 10-core machine. That contention
> produced spurious ~80 % "slowdowns" on `Dijkstra_Large` and
> `Brandes_RandomGraph` with implausible ±80–99 % sample variance — a
> physical impossibility, since **no commit between `v0.7.0` and
> `v0.8.0` touches `dijkstra.go`, `brandes.go`, `bfs_do.go`, `yen.go`,
> or `graph/mapper.go`** (the only non-test changes under `search/` are
> `floyd_warshall.go` and `kshortest_loopless.go`, neither on a
> benchmarked path), and the `allocs/op` / `B/op` were byte-identical
> across both tags throughout. That run was discarded and the comparison
> repeated under strict isolation (a build warmup followed by the timed
> runs, with no concurrent process on the machine), producing the clean,
> tightly-distributed figures below. As
> [v0.7.0's own note](v0.7.0.md#v060--v070-comparison) records for an
> analogous incident: **benchmark isolation is a precondition for a
> valid measurement**, not an optional nicety.

All benchmarks reported here exist **identically in both tags**, so
every comparison is like-for-like.

### Method

| Property | Value |
|----------|-------|
| Old (base) | `v0.7.0` tag (commit `bb3ad3a`), built in `git worktree` |
| New | release `HEAD` (`d9a915e`, 86 commits on top of `v0.7.0`) |
| Command | `go test -run='^$' -bench=<set> -benchmem -count=6` |
| Comparison | `benchstat old.txt new.txt` |
| Significance | `benchstat` two-sample test; `~` means *p* ≥ 0.05 (no significant change) |

| Environment | Apple M4 (10-core), macOS 26.5.1 (darwin/arm64), go1.26.5, GOMAXPROCS=10 |
| Isolation | Build warmup, then each side run to completion before the other started; no concurrent process on the machine during either run |

### Interpretation

- **No regressions on the guard-band set.** Every headline benchmark is
  statistically unchanged (`~`) between `v0.7.0` and `v0.8.0` except
  `Yen_K100`, whose **+0.84%** is significant by `benchstat`'s two-sample
  test but negligible in magnitude and within the ±1 % run-to-run band;
  its code path (`search/yen.go`) is unchanged since `v0.7.0`, so this is
  measurement variation, not a code regression. The two post-warmup,
  reusable-state traversal paths remain **zero-allocation** in both tags,
  and every `allocs/op` and `B/op` figure is unchanged.
- **`cypher/exec` is flat.** The geomean moves **−0.16%** and no single
  benchmark moves more than ±1.9 %, with mixed sign (`Project`/`Top`
  faster, `Distinct` slower) — the signature of run-to-run noise, not a
  systematic shift. Allocations are byte-for-byte identical on every row,
  confirming no code change touched these operators.
- **Consistent with the change set.** The release's functional work
  (constraint grammar, schema-DDL durability/atomicity, Cypher
  correctness, and security/DoS hardening) executes only on its
  respective code paths — none of which is exercised by a
  `Dijkstra`/`BFS`/`Yen`/`Brandes` traversal or a `cypher/exec`
  pipeline-operator benchmark — consistent with the flat results above.

## Load test — read-path concurrency sweep

CLAUDE.md requires a load-test report "at multiple concurrency levels
(1, 8, 64, 256, 1024 goroutines)". As in
[v0.7.0](v0.7.0.md#load-test--read-path-concurrency-sweep), we sweep
`GOMAXPROCS` over the `b.RunParallel` hot-key intern benchmark — the
tightest shared-state contention point in the read path, where every
goroutine interns the **same** key and competes for the same cache line.
Each figure is the median of 5 samples.

| Goroutines (`GOMAXPROCS`) | ns/op (median) | B/op | allocs/op |
|--------------------------:|---------------:|-----:|----------:|
| 1 | 7.70 | 0 | 0 |
| 8 | 95.11 | 0 | 0 |
| 64 | 90.68 | 0 | 0 |
| 256 | 90.05 | 0 | 0 |
| 1024 | 89.15 | 0 | 0 |

**Reading the sweep.** From 8 to 1024 goroutines (a 128×
over-subscription of the 10 physical cores) per-op latency stays **flat
at ≈ 89–95 ns/op with zero allocations** — the structure degrades
gracefully and predictably under massive over-subscription rather than
collapsing, so the bounded-resource and lock-contention mandates hold.
The single-goroutine figure (7.70 ns/op) reflects the absence of atomic
contention at `GOMAXPROCS=1`; the jump to the ≈ 89–95 ns/op plateau
happens once multiple goroutines genuinely contend for the same cache
line, and the plateau itself does not grow with further
over-subscription. This matches the v0.7.0 sweep (`mapper.go` is
unchanged since v0.7.0).

## Reproduce

```
# Headline / guard-band set (median of 6)
./scripts/run_headline_bench.sh

# Read-path concurrency sweep (median of 5)
go test -run='^$' -bench='^BenchmarkMapper_Intern_HotKey_Parallel$' \
  -benchmem -cpu=1,8,64,256,1024 -count=5 ./graph/

# cypher/exec set (median of 6)
go test -run='^$' -benchmem -count=6 \
  -bench='^(BenchmarkRowSlab_Alloc|BenchmarkDrain_Throughput|BenchmarkFilter_Throughput|BenchmarkProject_Throughput|BenchmarkLimit_Throughput|BenchmarkSort_10k|BenchmarkTop_10kN100|BenchmarkDistinct_10k)$' \
  ./cypher/exec/

# v0.7.0 -> v0.8.0 comparison (strict isolation; forced shipping toolchain)
git worktree add --detach /tmp/gg-v070 v0.7.0
GOTOOLCHAIN=go1.26.5 go test -run='^$' -bench=<set> -benchmem -count=6 ./search/... ./search/centrality/... ./cypher/exec/...   # in both trees
benchstat old.txt new.txt
git worktree remove /tmp/gg-v070
```
