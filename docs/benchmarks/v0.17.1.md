# Benchmark Record — GoGraph v0.17.1

This is the per-release benchmark record that `internal/docscheck`
(`TestPerReleaseBenchmarkReportExists`, rmp #1398) requires for every release.

## Scope

**No release-time benchmark campaign was run for `v0.17.1`.** Benchmark execution is not part
of the release path (see [docs/release.md](../release.md)). Every figure below is a
development-time measurement recorded in the rmp task log of sprint 368 (#3119 to #3121),
measured on the code this release ships. The rows measure different workloads, are **not
additive**, and **no whole-release delta is claimed**.

**No load test at the published 1, 8, 64, 256 and 1 024 goroutine concurrency levels was run for
this release.**

## Recorded measurements

| Change | Measurement | Source |
|---|---|---|
| Minted node keys and write-set state released on abort (rmp #3119, #3120) | cut `MATCH (a), (b), (c) CREATE ()` over 600 nodes, 5 s deadline: live heap after GC 1847.5 MB → 2.5 MB | rmp #3119, #3120; commit `78039599` |
| Released tail of hole ids kept out of memory (rmp #3121) | 1000 creates after a rollback of about 7.1 M ids: live heap 124.3 MB → 2.9 MB | rmp #3121; commit `54a2e218` |
| Dense Mapper paths after rmp #3121 | `Resolve` +0.9 % (p=0.089, not significant); `Walk` −3.5 % (benchstat, 10 interleaved rounds) | rmp #3121; commit `54a2e218` |

## Costs recorded

- Releasing the keys of an aborted transaction adds about 1.5 s to its rollback per about
  1.6 M released ids (rmp sprint 368 task log).
- Holes in the middle of a shard — nodes committed in the same shard while a large statement was
  rolled back — still cost about 16 B per id.

## Not measured for this release

- `v0.17.1` against `v0.17.0` on any whole-module workload.
- The concurrency ladder (1, 8, 64, 256, 1 024 goroutines).
